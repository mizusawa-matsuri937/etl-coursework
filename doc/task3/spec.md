# 任务 3 规格（电影页面筛选）

状态：2026-10-29 编写计划；同日用户同意假设全部按建议执行，并授权连续完成全部任务后再审核。实现中按页面实例修订 R11、R14、R16 与 AC04（见 design“分类规则”）。同日用户复核通过后，按已知问题修订 R11、R14、R15 与 AC04，规则版本升为 `t3r2`（见 design“规则版本 t3r2”）。设计见 [design](design.md)，执行顺序见 [tasks](tasks.md)，完成情况见 [checklist](checklist.md)。

## 目标

为采集清单中的全部 253,059 个产品各给出一个互斥分类（电影、非电影、合集、剧集、演唱会或其他、待确认）及可追溯的分类依据：从任务 2 已保存的 amazon.com 经典产品页快照中，按限定区域原样抽取字段作为证据，用有版本的规则分类；没有可用页面或证据不足的保留待确认。同时提交采集状态分布、电影识别数量、字段覆盖率与人工抽查结果，评论数据一条不删。

## 范围

- 包含：按清单状态与页面模板划分输入组；读取快照并核对哈希；限定区域的原始字段抽取与标签映射；规则分类、证据与冲突记录；解析与规则版本、幂等、分批恢复、规则版本差异；Airflow 编排；统计报告（采集状态与来源类型、输入组、分类、证据级别、字段覆盖率、按分类的评论数）；人工抽查样本的导出与标注导入。
- 不包含：重新请求页面或补爬；解析 `automation_title` 模板与被跳转到其他站点的页面；第三方或外部归档数据；字段值的规范化（标题标准化、日期语义、类型受控词表、人物实体）；电影或人物合并、`movie_id`；评论去重。这些属于任务 4 及以后。
- 约束：不修改任务 1、任务 2 的 spec、表结构、数据与测试；只读 `public`、`task2` 两个 schema 与 `outputs/task2/snapshots/`；沿用 Python + PostgreSQL + Airflow + Docker Compose；新表放在 schema `task3`；测试不访问外网、只写 `etl_test`；快照、导出与抽查表不提交到仓库。
- 依据：[作业说明](../../../作业/数据存储与管理_ETL作业说明.docx) 的任务 3（六种分类与依据、不能凭 DVD/Blu-ray 判电影、证据不足待确认、评论保留、采集状态分布与识别数量、成功率分母、来源分别统计）、第五部分（原始值与规范值分开、商品发售时间区别于上映日期）、第八部分（原始层与暂存层、可重复运行与恢复）、第十部分（电影/非电影/待确认数量、覆盖率分母、缺失推断核实分别统计、可追溯）；任务 2 的 [spec](../task2/spec.md) H11 与 [交接文档](../handoffs/2026-10-29-task2-part2-to-task3.md)。

## 规则

“作业要求”来自任务书，“用户选择”来自 2026-10-29 及以前的对话，“工程默认”是本轮实现基线。R01–R06 为输入与抽取，R07–R17 为分类，R18–R23 为统计，R24–R30 为工程。

- R01 [作业要求]：输入限定为一个抽取的任务 2 清单，所有读取都带 `extraction_id`；默认取最近一次全量清单构建的抽取，正式库为 `f1e8b845…`。
- R02 [作业要求]：清单每个 ASIN 在同一规则版本下恰好有一行分类，六类行数之和等于清单行数（正式库 253,059），不因缺少页面而剔除任何 ASIN。
- R03 [用户选择]：按清单状态、最后一次尝试的页面模板和最终域名，把每个 ASIN 归入且只归入一个输入组：`dp_page`（`success`、`www.amazon.com`、`dp_product_title`）、`automation_title`、`other_site`、`access_restricted`、`not_found`、`timeout`、`parse_failed`、`not_collected`；只有 `dp_page` 组解析页面。
- R04 [作业要求及用户选择]：`dp_page` 以外的七组一律为待确认，`pending_reason` 记组名，依据记清单状态与最后一次尝试；`not_found` 不判为非电影，`automation_title`、`other_site` 不进入任何数据样本，但计入全部分母。
- R05 [作业要求]：页面只从任务 2 快照读取，不重新请求；解压后用 `content_hash` 核对，快照缺失或哈希不一致时该 ASIN 为待确认（`snapshot_missing`、`snapshot_hash_mismatch`）并记质量问题，不使用该页内容。
- R06 [作业要求]：只从七个证据区域抽取：标题 `#productTitle`、面包屑、商品详情要点 `#detailBullets_feature_div`、商品概览 `#productOverview_feature_div`、商品详情表 `#productDetails_*`、署名行 `#bylineInfo`、已选格式 `#tmmSwatches`；导航、推荐、评论、广告与描述的文字不作依据，抽取文本时排除 `script`、`style`。
- R07 [作业要求]：每个抽取值保存区域、标签原文、区域内序号和原值（只压缩空白、去掉不可见方向符），并按有版本的标签映射给出规范字段键；不规范化值本身，未知标签保留、字段键为 NULL；署名行里的每个署名按页面顺序各占一行。
- R08 [作业要求]：分类取六个互斥值：`movie` 电影、`non_movie` 非电影、`collection` 合集、`tv_series` 剧集、`concert_other` 演唱会或其他、`pending` 待确认；各类的含义见假设 H05。
- R09 [作业要求]：载体只证明商品是视频节目。标题含 DVD、Blu-ray、VHS，或格式字段为这些载体，都不能单独构成电影依据；`movie` 必须另有作品级证据（导演、演员、正片片长、电影分级、电影类型）。
- R10 [工程默认]：规则按固定优先级判定，首个命中即定：非电影 → 剧集 → 演唱会或其他 → 合集 → 电影 → 待确认；每条规则有稳定的 `rule_id`，模式与阈值随规则版本记录，具体取值见 design。
- R11 [工程默认]：面包屑首级存在且不是 `Movies & TV`、证据区域内既没有视频载体或电视制式、也没有剧集、类别、导演、演员信号或标题里的载体、Film/Movie、演出与合集字样时为非电影；有这些信号但没有载体时为待确认（`conflicting_evidence`）；有载体时不论首级都按视频节目继续判定，首级不一致记为冲突证据；没有面包屑也没有载体时为待确认（`no_video_evidence`）。
- R12 [工程默认]：类别标签（概览 Genre 的各项与面包屑第 2 级起的各级）含电视类标签，或标题符合季、整部剧集、集数等剧集模式时为剧集。
- R13 [工程默认]：类别标签属于演唱会与音乐录像、健身、专题、体育等受控列表，或标题符合现场演出、健身、教学模式时为演唱会或其他。
- R14 [工程默认]：标题符合双片、三部曲、多片套装等合集模式时为合集（推断）；发行品牌名中的 “Collection”（如 Criterion Collection）和只由载体组成的括号说明（如 “(Blu-ray 3D / Blu-ray / DVD)”）不算合集依据；格式含 Box set、多碟只记为信号，不单独构成合集依据。
- R15 [工程默认]：“Various”“Artist Not Provided”“n/a” 等占位署名不算导演或演员。电影分两级：导演、正片片长、以及演员、电影分级、电影类型至少一项同时存在为结构化电影；只有正片片长加一项作品级证据，或无片长但有两项作品级证据为推断电影；都不满足为待确认（`insufficient_evidence`）。
- R16 [作业要求]：每个分类记录证据级别：命中强条件且条件全部来自结构化字段为 `structured`，用到标题模式或只满足 R15 的推断电影条件为 `inferred`，待确认为 `missing`；人工抽查结论另存，与自动分类结果分开。
- R17 [作业要求]：每个分类保存命中的 `rule_id`、规则版本和每条用到的信号；信号指向具体抽取字段（区域、序号、原值）与快照哈希、最终地址、采集时间；命中但未采用的其他类别信号记为冲突证据，同样可查。
- R18 [作业要求]：采集统计按清单六种状态报告，分母为全部产品数；成功采集率 = `success` 数 / 全部产品数。按来源类型分别统计实时采集、离线快照、第三方补充，不合并为一个成功指标。
- R19 [作业要求]：分类统计报告六类数量，以及与输入组、证据级别的交叉表；电影识别数量分结构化与推断；识别覆盖率 = 非待确认产品数 / 全部产品数，另报以 `dp_page` 页面数为分母的值。
- R20 [作业要求]：字段覆盖率按规范字段键报告有值数与比例，分母分别为电影类产品数、`dp_page` 页面数、全部产品数；页面没有该字段记缺失；本任务的字段值都直接来自页面，没有推断值。
- R21 [作业要求]：页面上的 Release date、Date First Available 等日期是商品版本信息，字段键标为商品发售日期候选，不作为电影上映日期；上映语义留给任务 6。
- R22 [作业要求]：评论不删不改：按分类汇总清单中的记录数、有效数、隔离数，各类之和加上无产品标识的记录数等于任务 1 的读取数；任务 3 不写任务 1、任务 2 的任何表。
- R23 [工程默认]：每次运行导出 `summary.json`、`report.md`、`classification.csv`、`field_coverage.csv` 到 `outputs/task3/<抽取>/<规则版本>/<run_key>/`，记录文件哈希；导出不含评论正文与整页 HTML。
- R24 [作业要求]：解析结果以（抽取、ASIN、解析版本）唯一，分类以（抽取、ASIN、规则版本）唯一；同版本重跑不新增也不修改行，只新增一条 `reused` 审计。
- R25 [作业要求]：规则变化时生成新规则版本，只重算分类、不重解析页面；旧版本分类保留，可列出两个版本间分类发生变化的 ASIN 与原因。
- R26 [作业要求]：分批处理：每批 ASIN 的解析、字段、分类与证据在同一事务提交；快照逐个流式读取，不一次全读进内存；中断后重跑只处理未完成的 ASIN；同一抽取同一版本同时只允许一个运行。
- R27 [作业要求]：由 Airflow DAG `amazon_products_task3_classify` 执行：检查输入 → 解析与分类 → 核对 → 收尾报告 → 门禁；确定性错误不重试，暂时错误最多重试 2 次，收尾成功不掩盖上游失败。
- R28 [作业要求]：人工抽查：从 `dp_page` 中按自动分类分层抽样，排除规则开发样本，导出带依据的抽查表由用户标注；导入后按类报告一致数、一致率与不一致实例，并注明只代表抽查样本。AI 不作标注，标注只存人工结论。
- R29 [工程默认]：表结构为迁移 `201`，放在 schema `task3`；所有运行记录解析版本、规则版本、标签映射版本与运行审计。
- R30 [工程默认]：测试用合成页面与注入的快照目录，不访问外网、只写 `etl_test`；任务 1、任务 2 的测试保持通过。
