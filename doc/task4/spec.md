# 任务 4 规格（定义并识别同一电影）

状态：2026-10-29 编写计划；同日用户确认引入 IMDb 数据、合并范围、人物比较方式与评价样本量（H01–H04），并同意其余假设按建议执行（H05–H11；H12、H13 为待验证的观察与估计）；实现未开始。设计见 [design](design.md)，执行顺序见 [tasks](tasks.md)，完成情况见 [checklist](checklist.md)。

## 目标

给“同一电影”一个可操作的定义，把任务 3 识别出的电影类商品归并为有稳定 `movie_id` 的作品，每个 ASIN 仍保留为独立的商品版本；合集通过商品与作品的多对多关系表达，剧集单独计数。匹配先标准化、再生成候选、再用年份、导演、主演、片长与作品类型验证；用 IMDb 公开数据作为外部作品 ID 和年份来源。判定分为自动合并、人工复核、不合并三档，保存证据、阈值、置信度与规则版本，检查聚类一致性，记录映射历史并支持纠正。最后用用户人工标注的 120 对独立样本报告自动合并的 Precision、Recall、F1。

## 范围

- 包含：全部 253,059 个 ASIN 的商品版本与版本属性；IMDb 固定快照的校验、流式装载与源记录定位；标题、语言别名、商品描述、人物姓名与片长的标准化；商品对 IMDb 作品、商品对商品两类候选的生成与验证；三档判定与合并决策；合集成员拆分与多对多映射；剧集的商品层处理；稳定 `movie_id`、映射历史、人工纠正与聚类一致性检查；规则版本差异、幂等、分批恢复与 Airflow 编排；统计报告与实例；评价样本与簇抽查的导出、标注导入和指标计算。
- 不包含：人物实体与 `person_id`（任务 5）；作品上映日期、年份与类型的最终取值（任务 6、任务 7）；评论去重与按作品的评分（任务 8）；完整的字段级血缘查询（任务 9）；重新请求页面或补爬；为没有可解析页面的 ASIN 寻找外部数据；剧集的季与单集实体；用 AI 或机器学习模型判定是否同一作品。
- 约束：不修改任务 1–3 的 spec、表结构、数据与测试，只读 `public`、`task2`、`task3`；沿用 Python + PostgreSQL + Airflow + Docker Compose，新表放在 schema `imdb` 与 `task4`；IMDb 原始文件放在仓库外并只读挂载，遵守其非商业使用条款，下载在实施时再取得一次用户许可；测试不访问外网、只写 `etl_test`；IMDb 文件、导出与评价表不提交到仓库。
- 依据：[作业说明](../../../作业/数据存储与管理_ETL作业说明.docx)的任务 4（同一电影定义、版本与例外、合集多对多、剧集、标准化与候选、验证条件、三档判定、聚类一致性、映射历史、实例展示）、第五部分（`movie_id` 与 `edition_id`、原始值与规范值分开、版本信息结构化）、第八部分（数据模型、可重复运行与恢复）、第十部分（合并前后数量、实体匹配评价）；[任务 3 交接文档](../handoffs/2026-10-29-task3-to-task4.md)。

## 规则

“作业要求”来自任务书，“用户选择”来自 2026-10-29 及以前的对话，“工程默认”是本轮实现基线。R01–R06 为输入与外部数据，R07–R11 为标准化，R12–R16 为同一电影的定义，R17–R19 为合集，R20–R27 为候选与判定，R28–R31 为标识、历史与纠正，R32–R36 为评价与实例，R37–R42 为统计与工程。

- R01 [作业要求]：输入限定为一个抽取、一个任务 3 规则版本和一个解析版本；默认为正式库抽取 `f1e8b845…`、规则 `t3r2`、解析 `t3p1`，所有读取都带这三个条件。
- R02 [作业要求]：清单里的每个 ASIN 恰好有一个商品版本行，ASIN 同时作为 `product_id` 与 `edition_id`，不作为 `movie_id`，不随合并删除；行数等于清单行数（正式库 253,059）。
- R03 [用户选择]：只有任务 3 的 `movie` 类与 `collection` 类进入匹配；`tv_series`、`concert_other`、`non_movie` 和有页面的 `pending` 只建商品版本，匹配状态为 `not_applicable`；没有可解析页面的 ASIN 匹配状态为 `no_page`。
- R04 [用户选择]：IMDb 只使用一个固定快照的 `title.basics`、`title.akas`、`title.crew`、`title.principals`、`name.basics`；每个文件记录下载地址、下载时间、大小与 SHA-256，装载前核对，不一致则拒绝装载。
- R05 [作业要求]：IMDb 文件流式解析，只装载 `titleType` 为 `movie`、`tvMovie`、`video` 的作品及其别名、导演与主要演职员，以及这些人的姓名；每行保留文件名与行号，`\N` 存为 NULL。
- R06 [作业要求]：每条匹配证据都指向源记录：页面字段指向任务 3 的抽取字段（区域、序号、原值）与快照哈希、最终地址、采集时间；IMDb 证据指向快照、文件、行号与 `tconst`/`nconst`。IMDb 作为第三方来源，与页面来源分开统计。
- R07 [作业要求]：原始标题原样保留；标题键按有版本的规则生成：Unicode 规范化、去重音、大小写折叠、`&` 与 `and` 统一、罗马数字与阿拉伯数字统一、去掉首冠词与标点、压缩空白。续集编号与副标题保留在标题键里。
- R08 [作业要求]：标题里的括号段与尾部说明按受控词表分类为载体、版本或剪辑、地区与制式、语言版本、包装、发行品牌、年份、未知；这些说明从标题键中去掉，原文另存为版本属性；括号里的四位年份记为“标题年份”。
- R09 [作业要求]：IMDb 的 `primaryTitle`、`originalTitle` 与全部 `akas` 别名都生成标题键，用于跨语言候选；每个别名记录地区、语言与来源行。
- R10 [用户选择]：导演、演员只在本任务内比较姓名键（去重音、大小写折叠、去标点），不生成 `person_id`；署名行优先、每行一人，只含一个逗号的行按“姓, 名”倒序，没有署名行才按逗号拆分详情要点；去掉中间名缩写的宽松键只算弱证据；“Various”等占位署名不参与比较。
- R11 [作业要求]：片长解析为分钟数。商品发售日期只作为版本属性保存，不作为作品年份的证据，也不参与匹配。
- R12 [作业要求]：同一电影指同一部创作作品。同一作品的 DVD、Blu-ray、VHS 载体，不同语言、配音、字幕、地区码与制式、包装、发行商和再发行，归为同一 `movie_id`，各自保留 `edition_id`。
- R13 [作业要求]：导演剪辑版、加长版、未分级版、修复版、重制版、上色版、周年版和不同长度的版本，归为同一 `movie_id`，在版本属性里记剪辑类型。标题带这类剪辑标记时，片长差异不算反证。
- R14 [作业要求]：翻拍、续集与同名不同作品分别建模。两边都有导演而姓名键完全不重叠，或两边年份相差超过 1 年，即为硬冲突，不得合并。
- R15 [工程默认]：IMDb 中 `tvSeries`、`tvMiniSeries`、`tvEpisode`、`short` 等不在 R05 范围内的作品不作为电影候选。电影类商品只在这些作品里有匹配时不关联，标为人工复核，原因为 `non_movie_title_type`。
- R16 [用户选择]：剧集商品只建商品版本，不建电影作品，不与电影混合计数，报告中单独计数；剧集的季与单集不在本任务建模。
- R17 [用户选择]：合集商品按显式分隔拆分成员：标题里的 “ / ”，括号内的成员列表，以及带 Double/Triple Feature 标记的 “A & B”。只接受 2–6 个成员，保留每个成员的原文与序号；拆不出的合集标为 `collection_unsplit`，暂不关联电影。
- R18 [作业要求]：每个合集成员按 R20–R25 单独匹配；采用的匹配建立关系类型为 `contains` 的商品–电影关系，带成员序号与决策依据。同一合集商品可以关联多部电影，同一电影也可以出现在多个合集里。
- R19 [作业要求]：评论仍归属商品。合集评论不复制给成员电影；按作品统计评论时只经 `edition` 关系计入，合集评论单列。各口径的记录数之和等于清单记录总数。
- R20 [作业要求]：候选分两类并记录生成器编号：商品标题键等于 IMDb 作品任一标题键时生成商品对作品候选，标题键相同的电影类商品两两生成商品对商品候选；每个商品的候选数有上限，超出时记录溢出，不静默截断。
- R21 [作业要求]：每个候选计算并保存验证特征：标题匹配方式，年份（标题年份与 IMDb `startYear`），导演重叠，演员重叠（页面演员对比 IMDb 的 actor/actress），片长差，IMDb 作品类型与类别。每个特征记录取值和所用源记录。
- R22 [作业要求]：仅凭标题相似、仅凭年份相同，或者缺少年份，都不能自动合并。自动合并必须同时满足：两边都有年份（IMDb `startYear` 或标题年份）；至少一位导演的姓名键完全一致，或至少一位演员的姓名键完全一致；没有 R14 的硬冲突。
- R23 [工程默认]：候选得分为各特征加权分之和，有硬冲突直接不合并；得分达到自动阈值、满足 R22 且领先第二名不少于规定差值为自动合并，达到复核阈值或与第二名并列为人工复核，其余不合并；权重、阈值、差值与置信度换算随规则版本记录，默认值见 design。
- R24 [工程默认]：一个商品最多自动关联一个 IMDb 作品；合集成员同样如此。没有自动关联的电影类商品单独成为一部作品（`page_only`），不被丢弃。
- R25 [作业要求]：商品之间的自动合并只有两条途径：两个商品自动关联到同一 IMDb 作品；或者没有 IMDb 关联，但两边标题键相同、标题年份相同，且导演姓名键有重叠。其他标题键相同的商品对按 R23 判为人工复核或不合并。
- R26 [作业要求]：每个多商品作品簇检查全部商品对的硬冲突，有冲突时把关联分较低的商品移出并改为人工复核，记录检查结果；人工复核与不合并的候选不连接任何簇，A≈B、B≈C 不会把冲突的 A 与 C 连带合并。
- R27 [作业要求]：每个判定写一条合并决策，内容包括：候选双方、判定档、得分、置信度、所用阈值、全部特征与证据、规则版本、运行，以及判定者（`system` 或 `human`）。未采用的候选同样保存。
- R28 [作业要求]：`movie_id` 由系统生成，不含 ASIN 或 IMDb 编号原文，生成后不复用；按锚点登记（有 IMDb 关联的以 `tconst` 为锚点，`page_only` 的以簇内最小 ASIN 为锚点），同一输入与规则版本重跑得到同一组 `movie_id`，锚点不变的作品在新规则版本下保持原 `movie_id`。
- R29 [作业要求]：每次生成映射都形成一个映射版本，记录商品到作品的映射行、版本之间的合并与拆分事件，以及合并前后的数量：参与商品、作品、多商品作品、单商品作品、待复核商品。旧版本保留，可以查询。
- R30 [作业要求]：支持人工纠正：导入“必须合并”“不得合并”“移出”三种人工决策，生成新的映射版本。人工决策优先于自动判定，与硬冲突矛盾时仍执行，但会标出。历史能显示被拆开或并入的商品。
- R31 [作业要求]：规则或输入（IMDb 快照、人工决策）变化时生成新的映射版本，只重算受影响的阶段，并能列出两个版本之间映射发生变化的商品与原因。
- R32 [作业要求]：规则开发样本与评价样本分开：按 `md5(标题键)` 排序，前 20% 的标题键属于开发池，只用于调整阈值；评价样本只从其余标题键抽取。
- R33 [用户选择]：评价样本为 120 对商品，分层抽取（层次见 design），覆盖跨版本、同名不同作品、翻拍、续集、合集成员对单片、标题相近但未被分块的商品对；导出表带双方原始标题、证据与页面地址，由用户逐对标注“同一 / 不同 / 不确定”，AI 不标注；“不确定”不计入指标，单独报告数量。
- R34 [作业要求]：用已标注的样本对计算自动合并的 Precision、Recall、F1，列出误合并与漏合并实例；分母为零时该指标记为“无定义”，不记为 0 或 1；人工复核覆盖率与待复核率单独报告；报告注明指标只代表评价样本。
- R35 [作业要求]：从评价池随机抽 20 个多商品作品簇，由用户检查是否混入不同作品，用于发现传递合并错误，结果单独报告。
- R36 [作业要求]：报告列出至少 5 组跨版本合并和至少 5 组易混淆而未合并的实例，每组附双方标题、判定档、关键特征与源记录；用户已标注过的实例注明标注结论。
- R37 [作业要求]：每次运行导出报告到 `outputs/task4/<抽取>/<映射版本>/<run_key>/` 并记录文件哈希，内容为合并前后数量、判定档分布、IMDb 关联与 `page_only` 作品数（第三方来源分开）、合集成员拆分与关联数、剧集商品数、各关系口径的评论记录数与候选溢出数；导出不含评论正文与整页 HTML。
- R38 [作业要求]：同一输入、同一规则版本、同一组人工决策重跑时，不新增也不修改目标行，只记一条 `reused` 审计。同一 IMDb 快照的重复装载同样复用。
- R39 [作业要求]：分批处理：每批商品的标准化、候选、特征与决策在同一事务提交；中断后重跑只处理未完成的批次。同一输入同时只允许一个运行。
- R40 [作业要求]：由 Airflow DAG `imdb_reference_task4_load`（校验文件 → 装载 → 核对 → 门禁）与 `amazon_movies_task4_match`（检查输入 → 标准化与版本属性 → 候选与判定 → 聚类与映射 → 核对 → 收尾报告 → 门禁）执行；确定性错误不重试，暂时错误最多重试 2 次，收尾成功不掩盖上游失败。
- R41 [工程默认]：表结构为迁移 `301`（schema `imdb`）与 `302`（schema `task4`）；每次运行记录标准化版本、规则版本、IMDb 快照、人工决策集与运行审计；不写任务 1–3 的任何表。
- R42 [工程默认]：测试只使用合成的页面字段与合成的 IMDb 小文件，不访问外网、只写 `etl_test`；任务 1–3 的测试保持通过。
