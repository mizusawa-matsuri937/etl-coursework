## 5. 已做的决定

- 合并范围：`movie` 参与合并，`collection` 拆成员建 `contains` 多对多，`tv_series` 只建商品版本；没有可解析页面的约 23 万个 ASIN 只建商品版本（`no_page`）。
- 剪辑版、修复版、不同长度版本与原作同属一个 `movie_id`；翻拍、续集、同名不同作品分开。
- 导演剪辑与加长版的片长差不算反证；缺年份不能自动合并；IMDb `tvMovie`、`video` 算电影候选，`short`、`tvSeries` 等只留标题用来识别 `non_movie_title_type`。
- 评价由用户一人标注；分歧的处理是证据不足就标 `unsure`，不计入指标。
- 真实 IMDb 文件里少量引用缺失（导演 86 行、主要演职员 618 行，占比不到 0.01%）按警告处理，不删行。

## 6. 环境与坑

- **环境变量**：`.env` 新增了 `IMDB_HOST_DIR=/Users/aqua_night/codex_project/数据存储与管理/imdb`（`.env` 不入仓库）；`.env.example` 里有说明。留空时挂载 `tests/fixtures/task4`（里面没有快照，只让容器能启动）。
- **测试会清空 etl_test**：集成测试会话开始时清空 `etl_test`（含 `task4`、`imdb`）。真实 scheduler 端到端要在测试之后从头准备：`scripts/seed_task4_e2e.py` 准备合成数据，`IMDB_HOST_DIR` 要临时指向合成快照目录，步骤见 runbook 第 2 节；做完用 `docker compose up -d` 回到正常配置（Airflow 服务会按 `.env` 重新挂载真实 IMDb 目录）。
- **Airflow 服务要重建才会改挂载**：改 `IMDB_HOST_DIR` 后必须 `docker compose up -d`，否则 DAG 看不到文件。
- **步骤共用一条运行**：匹配 DAG 的三个步骤靠 `task4.run.airflow_run_id`（等于 DAG 的 run id）找回同一条运行。同一个 run id 不能重复触发（Airflow 本身也不允许），换 run id 重做。
- **抽取锁**：同一抽取同时只能有一个匹配运行，拿不到锁是确定性失败（不自动重试）。手工导入人工决策也会拿同一把锁。
- **规则版本**：代码里的 `RULE_VERSION`/`DEFAULT_RULES` 仍是 t4r1（测试依赖其数值），正式运行与 DAG 参数默认值是 `CURRENT_RULE_VERSION = t4r2`；新增规则版本必须登记到 `match.RULESETS`，不要改已登记的版本。
- **评价集一旦导出就不要再改规则**：评价表按 `map0002` 导出，规则已冻结。如果又改规则，`metrics` 会提示“评价集已被看过，不再独立”，需要在报告里说明（任务 3 的教训）。`eval_pairs.csv` 与 `cluster_sample.csv` 已存在时导出命令拒绝覆盖，以免丢失标注。
- **开发池**：1,967 个标题键、2,105 个实体，按 `md5(标题键)` 前 20% 冻结在 `task4.dev_pool`；评价样本不含这些标题键。
