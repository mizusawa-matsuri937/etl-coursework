## 4. 评价

- 120 项六层盲测样本 `ev_rd0001`；AI（Claude）只读盲测表预填草稿，付林轩 2026-11-03 审核后确认“都没有问题”，全部采纳导入（`same` 96、`different` 23、`unsure` 1）。不是独立手工标注；存疑项依据是盲测表字段比对，没有逐项外部核查。
- 指标（只代表分层样本）：合并精确率 0.975（39/40）、不合并正确率 0.5（20/40）、近似评论同一性比例 0.95（19/20，只描述）、统计组同片率 0.9474（18/19，`unsure` 1）。
- 主要弱点：`V3` 一半是被分进不同家族的同作品版本（家族阈值漏合并）；`V6` 一半是同一用户在同一商品上改摘要或隔期重贴（内容键只用原值，不合并）；统计组有同系列不同集的误连。改进建议见 report 第 8 节，均未实施。

## 6. 环境用法与踩过的坑

- 正式库只读查询带 `SET default_transaction_read_only = on;`；库名由环境变量 `ETL_DB_NAME` 决定，演练用 `docker compose --profile crawl run --rm -T -e ETL_DB_NAME=etl_t8_rehearsal crawler python -m ...`。
- **业务库副本演练**：建副本前停 Airflow 三个服务（`CREATE DATABASE … TEMPLATE etl_movies` 要求模板库无连接），建好立即恢复。`TEMPLATE` 默认按 `WAL_LOG` 复制，一次写了约 27 GB WAL，磁盘一度只剩 814 MB；建库和删库后都要执行 `CHECKPOINT`（runbook 第 3 节）。
- **先冻结再运行**：`evaluate freeze` 必须在首次 `runner run` 或 DAG 之前，否则 `frozen_before_first_run` 为 false。
- **查询计划**：去重核验的大连接被规划器选成嵌套循环（10 分钟不完成），只在该事务里关掉嵌套循环、调大 `work_mem`；并行哈希会用满 1 GB 的 `/dev/shm`（报 DiskFull），已 `SET LOCAL enable_parallel_hash = off`。
- **夹具**：任务 8 夹具经任务 1 自己的装载器从合成 gzip 生成，与正式库同形；`tests/integration/conftest.py` 已增加 `DROP SCHEMA IF EXISTS task8`。
- 全量测试：`docker compose --profile test run --rm etl-test pytest -q tests`，2026-11-03 为 1,186 passed。
