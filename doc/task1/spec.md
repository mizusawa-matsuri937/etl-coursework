# 任务 1 规格

状态：第一轮计划，2026-10-22 按文档规范重整；规则与 AC 定义未因实施而改动，实施与验收状态见 checklist。设计见 [design](design.md)，执行顺序见 [tasks](tasks.md)，完成情况见 [checklist](checklist.md)。

## 目标

全量、可重复地抽取 Amazon 评论并装载 PostgreSQL，保留每条原始记录及异常证据，通过 Airflow 完成数量核对与可复现报告。

## 范围

- 包含：已有源文件校验、流式分批解析、基础字段规范化、有效/隔离记录管理、来源定位、数据库装载、幂等与恢复、Airflow 编排、资源试跑、全量统计及复现说明。
- 不包含：产品页面采集、电影筛选、电影/人物合并、上映信息补全、逻辑评论去重和完整字段级血缘系统。为后续任务保留来源、字段位置、规则版本和批次信息。
- 已确认约束：Python、PostgreSQL、Docker Compose；使用课件中的 Airflow，并在任务 1 接通“校验 → 解析与装载 → 核对 → 报告”。
- 原始材料和数据保持不变，样本不能替代全量验收。单机实现，暂不增加 UI、分布式计算或网页采集。
- 依据：[作业说明](../../../作业/数据存储与管理_ETL作业说明.docx) 的任务 1、评论字段、ETL 架构/恢复、数量/复现要求，以及 [ETL 课件](../../../ETL.pdf) 的工具清单。具体工程结构与参数见 design。

输入字段使用以下八个完整行首前缀：

```text
product/productId:
review/userId:
review/profileName:
review/helpfulness:
review/score:
review/time:
review/summary:
review/text:
```

## 规则

“作业要求”来自任务书，“用户选择”来自本次对话，“工程默认”是当前实现基线。R01–R12 保留原有主题；字段校验、统计口径等细则拆为 R13–R25。

- R01 [作业要求]：保留来源 URL、下载时间、大小、SHA-256、程序和规则版本，未知值注明未知。下载与验证时间分开记录，本地哈希不冒充官方值；缺少必要输入或大小/哈希不符时，装载前失败。
- R02 [作业要求]：流式分批处理，不一次性读入全文件或全部评论。全量模式无记录数上限，必须读到 EOF 并验证 gzip；样本完成与整份文件完成分别报告。
- R03 [作业要求及工程默认]：支持 LF、CRLF；仅移除行结束符后为空的行才是记录分隔符。连续空行不生成记录；非空块按顺序编号，EOF 无末行换行也保留最后一条。
- R04 [作业要求]：同文件同序号的 `source_review_id` 重跑不变，不同序号的 ID 不同。保留文件版本、序号、物理行号、解压字节位置和原始哈希；源记录 ID、抽取版本与执行 ID 分开。
- R05 [作业要求及工程默认]：每个非空块只能归为 valid 或 quarantined，不得静默跳过。valid 要求结构明确、严格解码成功且产品 ID 非空；非产品字段缺失、空用户、空正文或非法数值可保留并记问题。
- R06 [作业要求及工程默认]：读取数＝有效数＋隔离数；记录明细、有效/隔离子集与已提交批次统计一致。所有统计限定同一抽取版本，不混入样本、其他规则版本或失败重试计数。
- R07 [作业要求及工程默认]：原值与规范值分别保存。缺失字段的原值为 NULL，存在但为空的原值为空字符串；同时记录字段存在性、已识别前缀和字段起始行。非法规范值置 NULL 并记问题，具体字段规则见 R16–R21。
- R08 [用户选择及工程默认]：使用 PostgreSQL，校验主键、外键、唯一性和数值约束。源、抽取、执行、批次和记录关系明确；有效/隔离子集互斥完备，同键不同内容报错。业务库、Airflow 元数据与测试库隔离，重启保留业务数据。
- R09 [作业要求]：同输入、规则和有效配置重跑，不增加结果、问题或已提交批次，可新增执行审计。数据与检查点原子提交；提交前后中断均能恢复到无中断结果。不匹配版本不得复用检查点，gzip 恢复可重扫。
- R10 [作业要求及用户选择]：Airflow 实际执行校验、解析装载、核对和报告，保留参数、依赖与日志。确定性错误不盲目重试，暂时错误重试有上限；失败保留原因、已提交进度和不完整状态，收尾成功不能掩盖上游失败。
- R11 [作业要求]：交付版本、配置、命令、作业定义、数据模型/字段字典、固定样本及预期、实测报告、异常依据和恢复说明。预备镜像后可离线复现样本；路径可配置，不提交密码或全量数据。记录 AI 辅助与人工核验方式，未执行事项不标完成。
- R12 [作业范围选择]：任务 1 不做逻辑评论去重，删除原始记录数为 0。内容相同的不同源记录都保留；重复候选须说明统计口径，不能直接视为应删除记录。
- R13 [工程默认]：仅识别范围中列出的八个完整行首前缀，字段可重排；前缀后最多移除一个分隔空格，不全局切冒号或去空白。重复前缀、未知字段、无法解释的续行或边界歧义整体隔离，不覆盖或猜拆；其他格式须凭证据修订规则与测试。
- R14 [工程默认]：默认严格按 UTF-8 解码。解码失败、NUL、结构歧义或缺少/空白产品 ID 时隔离，完整保留原始字节；不忽略错误或替换字符。编码变更须有证据并更新规则版本。
- R15 [作业要求及工程默认]：每个质量问题记录字段、问题码、严重程度、原值或字节证据及规则版本。一条记录可有多个问题；问题行数与有问题的记录数分别统计，日志不逐条输出正文。
- R16 [工程默认]：产品保留 `product_id_raw`，关联用 `product_id` 保持原标识，不改大小写、不补字符。缺少、空值或纯空白使记录隔离；非常见 10 位字母数字格式只记问题。ASIN 是产品 ID，不是电影 ID。
- R17 [工程默认]：用户保留 `reviewer_id_raw`，非空 ID 原样保留；空或纯空白的规范值为 NULL。`unknown` 等非空字面量保留并单列频次；不凭昵称补 ID 或合并用户，不擅自把字面量解释为缺失或不同用户。
- R18 [工程默认]：昵称、摘要和正文原样保留，区分缺失与空字符串；昵称缺失可为空，空正文记问题。摘要和正文不截断、不翻译、不改写，不去 HTML 或压缩空白。
- R19 [工程默认]：有用票保留原值，规范票数须为两个非负整数且分子≤分母。`0/0` 保留两项票数 0，比率为 NULL；非法值的票数及比率均置 NULL 并记问题。
- R20 [工程默认]：评分保留原值，规范值用 Decimal，须为 1 至 5 的有限数，可含小数。非法或缺失时规范值为 NULL 并记问题，不截断到边界。
- R21 [工程默认]：时间保留原值，仅接受 Unix 整数秒并转 UTC，不猜测毫秒或使用本地时区。整数溢出、非法值或无法转换时保留原值并记问题；不因超出官方时间范围删除记录。
- R22 [工程默认]：observed 产品/用户数统计所有记录中可明确识别的非空、非纯空白原始 ID，含隔离记录；valid 数仅统计有效记录，两组分别报告。正文解码失败仍尝试从字节识别唯一 ID；冲突或 ID 解码失败计为无法识别，不当作缺失。
- R23 [工程默认]：报告分别列出读取、有效、隔离、有质量问题的记录数及问题行数；用户字段缺失与存在但空白分别计数。按 R22 分别列出 observed/valid 产品和用户去重数、无法识别数量，以及删除原始记录数。
- R24 [作业要求及工程默认]：全量基准为评论 7,911,684、产品 253,059、用户 889,176；评论比较全部读取数，产品/用户先比 observed 再说明 valid 差异。不得人为凑数；不变量失败即失败，差异未解释保持 `review_required`，有依据的审阅通过后才声明通过。
- R25 [作业要求及工程默认]：极长行/记录也须限制内存，超限数据完整旁路保存并记录原因。资源报告区分实测、估算和预算，说明全量估算依据；低磁盘空间时保留已提交检查点后停止。

### 固定样本

计划通过 `tests/fixtures/build_fixtures.py` 生成可重复的 gzip，预期值保存在 `tests/fixtures/task1_cases.json`。以下 10 条均为人工构造数据。除列出的变化外，每条有八个前缀、普通昵称/摘要/正文、评分 `5`、helpfulness `1/1`、时间 `0`。第 2 条原始内容与第 1 条完全相同；第 10 条位于 EOF，无结尾换行或分隔空行。

| 记录 | 产品 ID | 用户 ID | 特殊输入 | 预期分类 |
|---|---|---|---|---|
| 1 | AAAAAAAAAA | USER_A | 正文含冒号、逗号、制表符、反斜杠、行内前缀字样 | valid，正文原样 |
| 2 | AAAAAAAAAA | USER_A | 内容与 1 相同 | valid，ID 与 1 不同 |
| 3 | AAAAAAAAAA | 空字符串 | 昵称/摘要为空，helpfulness 为 `0/0` | valid，用户/比例为 NULL |
| 4 | BBBBBBBBBB | USER_B | 评分 `6`、helpfulness `2/1`、时间 `bad` | valid，三项问题与 NULL 规范值 |
| 5 | BBBBBBBBBB | USER_C | 正文无效 UTF-8 字节 | quarantined，ID 仍可识别 |
| 6 | CCCCCCCCCC | USER_D | 重复 `review/score:` 前缀 | quarantined，保留两值 |
| 7 | 缺失前缀 | USER_E | 缺少产品字段 | quarantined，保留用户和记录号 |
| 8 | DDDDDDDDDD | USER_F | 正文含 NUL | quarantined，字节可回放 |
| 9 | EEEEEEEEEE | unknown | 用户为非空字面量 `unknown` | valid，不自动转 NULL |
| 10 | FFFFFFFFFF | USER_G | 正文前缀存在但为空，EOF 无换行 | valid，空正文有记录 |
